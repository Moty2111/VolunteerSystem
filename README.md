# VolunteerSystem

Система учёта волонтёров: мероприятия и запись на них, назначения, навыки,
партнёры, отчёты и роли пользователей. Клиент — React + TypeScript + Vite,
API — ASP.NET Core 10 + Entity Framework Core, база — SQL Server.
Карта мероприятия использует Nominatim для поиска адреса и OpenStreetMap для отображения.

## Локальный запуск

Нужны Node.js 24, .NET SDK 10 и работающий SQL Server.
Строка подключения по умолчанию использует Windows LocalDB (`MSSQLLocalDB`).
На macOS/Linux нужен отдельный SQL Server и переменная окружения
`ConnectionStrings__DefaultConnection` с его строкой подключения.
База и демонстрационные данные создаются сервером при первом запуске.

Из корня репозитория:

```sh
npm run install:all
npm run dev
```

Откройте адрес, напечатанный после «Проект запущен».
По умолчанию это `http://localhost:61000`, API — `http://localhost:5084`.
Если порт занят другой программой, выбирается следующий свободный порт;
адрес API автоматически передаётся прокси клиента. Чужие процессы не останавливаются.
Повторный запуск распознаёт уже работающий экземпляр по служебному JSON-ответу.
Ctrl+C останавливает запущенные этой командой процессы вместе с дочерними Vite/.NET.
Процессы, которые уже работали до запуска команды, остаются под управлением их исходного терминала.

Настройки: `DEV_SERVER_PORT` — предпочтительный порт клиента,
`DEV_API_PORT` — предпочтительный порт API. Поиск ограничен следующими 100 портами.
Два запуска строго одновременно могут столкнуться при занятии порта; в этом случае
запуск завершится с ошибкой, повторите команду после завершения первого запуска.

HTTPS необязателен. Для него задайте `DEV_HTTPS=1`; нужен .NET dev-сертификат.
При необходимости отдельно выполните `dotnet dev-certs https --trust`.
Обычная сборка сертификаты не создаёт и доверие к ним не меняет.

Для отдельных процессов: `npm run dev:api` и `npm run dev:web`.
При отдельном запуске используется фиксированный порт; автоматический подбор выполняет `npm run dev`.
В Visual Studio при запуске обоих проектов клиент запускает только Vite,
чтобы не создавать второй экземпляр API.

## Проверки

```sh
npm test
npm run build
npm --prefix volunteersystem.client run lint
volunteersystem.client/node_modules/.bin/tsc --noEmit -p volunteersystem.client/tsconfig.json
```

Тесты запускаются на Node.js 24 без отдельного тестового фреймворка.
Интеграционный тест запускает настоящий Vite и временную замену API,
проверяет конфликт портов, прокси, повторный запуск и освобождение портов.
Проверка группы дочерних процессов выполняется на macOS/Linux;
Windows-ветка с `taskkill /T` требует отдельной проверки на Windows.

## Исправления по жалобам на карту, фильтры и запуск

- Статус мероприятий и город/активность волонтёров раньше применялись только
  кнопкой «Обновить». После неё клиент сохранял уже отфильтрованную выборку,
  и сброс фильтров не восстанавливал полный список. Теперь сервер возвращает
  полный список, все фильтры применяются сразу на клиенте. Поиск убирает пробелы по краям.
- После уменьшения числа волонтёров текущая страница могла оказаться за пределами
  списка. Теперь отображаемая страница ограничена актуальным числом страниц.
- Карта могла зависнуть на запросе без таймаута; запрет sessionStorage ломал эффект,
  а ошибка записи кэша отбрасывала успешно найденные координаты. Теперь есть таймаут
  8 секунд, проверка координат, безопасный кэш, объединение одновременных одинаковых
  запросов и защита от показа старого адреса после переключения мероприятия.
- Занятый порт клиента раньше считался признаком работающего приложения независимо
  от его владельца. Vite завершался с кодом 0, а общий запуск останавливал процессы.
  Теперь проверяется идентификатор приложения и соответствие прокси API; чужие порты обходятся.
- Остановка убивала только оболочку npm, могла оставлять Vite и удерживать порт.
  Теперь останавливается всё дерево запущенных процессов, с ожиданием завершения.
- `dev:api` ссылался на отсутствующий `package.json` сервера; теперь вызывает `dotnet run`.
- Конфиг Vite создавал/доверял сертификат даже при production-сборке. Теперь HTTP
  работает без сертификата, а HTTPS включается явно только для локального сервера.
- Самописный прокси повторял также POST/PUT при сетевой ошибке, включая обрыв после
  обработки запроса сервером. Это могло повторить запись. Используется штатный прокси Vite
  без автоматического повтора операций записи.

Ограничения карты: часть демоадресов неоднозначна («ДК «Заря»», «Центральная библиотека»
без города). Для точной метки нужны город и полный адрес; первый результат геокодера
не гарантирует нужное место. При недоступности внешнего поиска остаётся ссылка на Яндекс.Карты.
Более надёжный следующий шаг — сохранять выбранные организатором координаты в БД.
